## 学習エンジン（v2 — FSRS-6）

単語帳の間隔反復を SM-2（1988年の SuperMemo）から **FSRS-6** へ移行しました。
同じ復習回数でより高い記憶保持率を得るための変更です。

### アルゴリズム

`js/fsrs.js` に DSR モデルを実装しています。

| 変数 | 意味 |
|---|---|
| **D** — Difficulty | その単語の覚えにくさ（1–10） |
| **S** — Stability | 想起率が 90% まで落ちるまでの日数 |
| **R** — Retrievability | 今この瞬間に思い出せる推定確率 |

SM-2 は「間隔 × ease」の乗算だけで忘却曲線を持たず、復習が遅れた／早すぎた
情報を捨てていました。FSRS は経過日数から R を推定し、**R が目標記憶率まで
落ちる日**を次回復習日とします。遅れた復習が記憶をより強化する効果
（spacing effect）も係数に取り込まれます。

### 導入した仕組み

1. **4 段階評価** — 「もう一度 / 難しい / 普通 / 簡単」。
   3 段階では「思い出せなかった」と「苦しかったが思い出せた」を区別できず、
   両者が同じラプス扱いになっていました。
2. **学習ステップ**（1分 → 10分）— 初回学習日に当日中に複数回想起させて定着させる。
3. **再学習ステップ**（10分）— 忘れた単語は当日中に立て直してから間隔を再開する。
4. **想起率順の出題** — 期日順ではなく「最も忘れかけている単語」から出す。
5. **1 日の上限**（新規 20 / 復習 150）— 復習の雪崩を防ぎ、継続率を上げる。
6. **交互出題（インターリービング）** — 新規と復習を混ぜて長期保持を上げる。
7. **リーチ検出** — 8 回以上忘れた単語を隔離候補として通知する。
8. **目標記憶率の可変化** — 80 / 85 / 90 / 95% から選択。復習量とのトレードオフを学習者が決められる。
9. **間隔プレビュー** — 各ボタンに次回出題時期を表示（メタ認知支援）。
10. **キーボード操作** — `1`–`4` で評価、`Space` で裏返し。
11. **復習ログ記録** — IndexedDB `reviewLog` に生ログを蓄積。
12. **パラメータの個人最適化** — 下記参照。

### パラメータの個人最適化

既定の 21 パラメータは「多数派の記憶」に合わせた汎用値です。実際の忘却の速さは
人によっても教材によっても違うため、自分の復習ログから係数を推定し直すと
復習日の予測精度が上がります。学習設定パネルの「最適化する」から実行できます。

- **手法** — 各単語の復習系列を FSRS で再生し、復習時点の想起率と実際の結果との
  対数損失を Adam（勾配は中心差分で近似）で最小化します。
- **過学習対策** — 単語単位で 8:2 に分割し、**学習に使っていない 2 割**で採否を判断します。
- **採用条件** — 次の両方を満たしたときだけ適用します。片方でも欠ければ既定値のままです。
  1. 対数損失が 0.5% 以上改善している
  2. 較正誤差（RMSE）が悪化していない — 「90% と言ったとき本当に 90% 当たるか」が
     崩れる最適化は、たとえ対数損失が下がっても採用しません
- **必要な履歴** — 1,000 件以上。合成データでの計測では 640 件では既定値を上回れず、
  1,600 件を超えると検証データ上でも安定して改善しました。
- **実行環境** — Web Worker で実行するため UI は固まりません（Worker 不可の環境では
  メインスレッドにフォールバック）。学習に使う単語数は 1,200 に上限を設け、
  端末上での実行時間を抑えています。
- いつでも「既定値に戻す」で元に戻せます。

### 既存データの移行

旧 SM-2 の状態は読み出し時に自動変換されます（破壊的変更なし）。

- `interval`（日） → 安定度 S の初期値
- `easeFactor` → 難易度 D へ反転写像（EF 2.5 → D 3.5 / EF 1.3 → D 10）

IndexedDB は v1 → v2 へ自動アップグレードし、`reviewLog` と `settings` ストアを追加します。

### ファイル構成

| ファイル | 役割 |
|---|---|
| `js/fsrs.js` | FSRS-6 コア（忘却曲線・メモリ状態更新・間隔算出） |
| `js/srs.js` | スケジューラ（学習ステップ・リーチ・SM-2 移行） |
| `js/vocabulary.js` | 学習キュー・上限制御・復習ログ・設定同期 |
| `js/fsrs-optimizer.js` | パラメータ個人最適化（損失計算・Adam・検証分割） |
| `js/optimizer-worker.js` | 最適化のバックグラウンド実行 |

## 発音練習（ベトナム語の声調）

iPhone / Android タブレットでの利用を前提にした、**端末内で完結する**発音評価です。
外部 API を使わないため通信も課金も発生せず、オフラインでも動作します。

### なぜ声調なのか

日本語話者にとってベトナム語で最も通じなくなる原因が声調です。
`ma / mà / má / mạ / mả / mã` は声調だけで別の単語になります。

商用の発音評価 API はこの部分をカバーしません。Azure は vi-VN の発音評価に
対応していますが、**韻律（prosody）評価は en-US 限定**のため、声調の良し悪しは
測れません。そこで自前で実装しています。

### しくみ

```
録音 (AudioWorklet, 生PCM)
  → 16kHz へダウンサンプル
  → 自己相関で F0 追跡（YIN の累積平均正規化）
  → 半音スケール + 話者平均で正規化（声の高さの個人差を吸収）
  → 声門閉鎖の強さを短時間エネルギーの急落から推定
  → DTW でお手本の輪郭と比較（発話速度の違いを吸収）
  → 採点 + 日本語での具体的な助言
  → FSRS に記録（苦手な声調ほど早く再出題）
```

**声門閉鎖の検出が要です。** F0 の輪郭だけでは `huyền ↔ nặng`、`ngã → sắc` が
分離できません（合成音声での判別率 87.3%）。エネルギーの急落を特徴量に加えると
98.3% まで上がります。nặng と ngã はこの「喉の詰め」で他と区別される音だからです。

### 声調の自動抽出

ベトナム語の声調は綴りで完全に決まるため、Unicode 結合文字へ分解すれば
機械的に取り出せます（`js/tones.js` の `toneOfSyllable`）。
既存の語彙データ 300 語に手作業でアノテーションする必要はありません。

`â ê ô ă ơ ư` が持つ記号は母音の種類を表すもので声調記号ではないため、
声調として扱う 5 つの結合文字だけを対象にしています。

### 端末ごとの注意点

- **HTTPS 必須**（GitHub Pages / Firebase Hosting はどちらも該当）
- iOS Safari は AudioContext をユーザー操作の中で `resume()` する必要があるため、
  録音は `pointerdown` から開始しています
- サンプルレートは端末が決めます（iPhone は 48kHz、環境により 44.1kHz）。
  固定値を仮定せず、実際の `ctx.sampleRate` を解析へ渡しています
- `echoCancellation` / `noiseSuppression` / `autoGainControl` はすべて無効化します。
  自動ゲイン調整はエネルギーの急落をならしてしまい、声門閉鎖を検出できなくなります
- 画面を離れるときにマイクを解放します（iOS で録音インジケータが残るため）
- AudioWorklet が使えない端末では ScriptProcessor へフォールバックします

### ファイル構成

| ファイル | 役割 |
|---|---|
| `js/pitch.js` | F0 追跡・正規化・声門閉鎖検出・DTW |
| `js/tones.js` | 6 声調の定義・綴りからの声調抽出・採点・助言生成 |
| `js/audio-recorder.js` | マイク録音（iOS/Android 対応、権限処理） |
| `js/recorder-worklet.js` | 生 PCM 取り込み用 AudioWorklet |
| `js/pronunciation.js` | 練習キュー・評価・FSRS 連携 |
| `data/vi-tones.json` | 最小対語ドリル（5 セット / 34 項目） |

### 検証状況

実ブラウザ（Chromium）で以下を確認済みです。

- AudioWorklet 経由の取り込み → 採点までの全経路
- 6 声調すべての判定一致（44.1kHz / 48kHz 入力）
- 誤発音の検出と助言生成
- FSRS への記録と再出題

なお**実際の人間の音声での精度は未検証**です。上記はすべて合成音声によるもので、
実発話は共調音・環境雑音・個人差があるため精度は下がります。
実機での確認が必要です。

## シナリオ会話

全 50 本。Phase 1（30本）は教科書的な基本表現、Phase 2（20本）は
**旅行・生活でネイティブが実際に使う言い回し**を扱います。

### Phase 2 の方針

教科書の英語・ベトナム語は文法的に正しくても、現地では不自然に響くことがあります。
Phase 2 では実際に使われる形を優先し、なぜそう言うのかを解説として添えています。

| 場面 | 教科書的 | 実際に使われる形 |
|---|---|---|
| 注文する | I want a coffee. | Can I get a coffee? |
| 値段が高い | That's expensive! | That's a bit steep. |
| 断る | No, I can't. | I'd love to, but ... / I'll pass this time. |
| 聞き返す | Please say again. | Come again? / Could you slow down a bit? |
| 会計 | Please give me the bill. | Check, please! / Tính tiền! |

ベトナム語では特に次の点を扱っています。

- **呼びかけの `ơi`** — `Anh ơi!` `Chị ơi!`。これが無いと呼びかけとして成立しません
- **人称の使い分け** — 相手の年齢で `anh / chị / em / cô` が変わります
- **`Ăn cơm chưa?`** — 直訳は「ご飯食べた？」ですが、実際は挨拶として使われます
- **文末詞** — `ạ`（敬意）`nhé`（親しみ）`mà`（軽い反論）で印象が大きく変わります
- **南北差** — `rẽ trái`（北）/ `quẹo trái`（南）など、併記しています

### 内訳

| 分類 | 本数 | 内容 |
|---|---|---|
| 旅行 | 10 | 入国審査、配車アプリ、屋台、値段交渉、薬局、SIM購入、道案内、ホテルの不具合、カフェ、予約トラブル |
| 生活 | 10 | 近所の立ち話、大家への修理依頼、荷物受取、美容院、誘う、断る、割り勘、天気の雑談、気遣い、聞き返し |

115 ターン中 84 ターンに解説を付けています。レベルは A2 が 14 本、B1 が 6 本。

### データ形式

`data/scenarios.json` の各ターンに任意の `note` を持たせられます。
既存の Phase 1 には `note` が無く、その場合は何も表示されません（後方互換）。

```json
{
  "speaker": "A",
  "en": "That's a bit steep.",
  "vi": "Đắt quá!",
  "ja": "ちょっと高いですね。",
  "note": "a bit steep は「ちょっと高い」の婉曲。..."
}
```

なお Phase 2 のベトナム語は一般的で広く使われる表現を選んでいますが、
**ネイティブによる確認は経ていません**。地域差・世代差のある言い回しも含まれます。
